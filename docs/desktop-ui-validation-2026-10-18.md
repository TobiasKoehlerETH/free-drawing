# Desktop UI validation — 18 October 2026

The minimal Python/Qt desktop app accepts one STEP file, generates a drawing locally, and opens its TechDraw sheet in FreeCAD. The final UI uses black, white and grayscale with a single drop area and file-selection button.

## Verified workflow

A real Qt drag-enter and drop event supplied a copy of the user's silicone-cap STEP file, including a space in its filename. The normal worker generated an FCStd, PDF, preview and inspection reports in a new folder. It reopened the drawing and found no changed dimensions or references. The launcher then opened FreeCAD and confirmed that its active view was `MDIViewPagePy`.

The end-to-end run completed in 102.2 seconds. The input hash was unchanged. Evidence is in `.scratch/ui-preview/e2e.json`, with idle and completed UI renders beside it. The saved output is under `.scratch/ui-preview/Drawings/silicone cap-20261018-123721/`.

The generated drawing retains the engine's known review findings. The app reports these through **Review notes**; it does not label the drawing as approved for manufacturing. Saved-dimension integrity failures block automatic opening, while a user can still open the retained draft for investigation.
